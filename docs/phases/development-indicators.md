# Development-storage indicators — 0.12.0

The user requested small development indicators, including debug outputs, older Git history, agent workspaces and evidence about whether files can be removed or recovered from a remote. This extends the existing Storage and Developer artifacts surfaces; it does not add removal authority.

Storage's bounded map/ranked entries show compact disclosures for recognized build/tool output, Rust `target/debug`, Xcode Debug products, dependencies/environments, indexed Git projects, Git metadata, and `.codex/worktrees`, `.claude/worktrees` or `.cursor/worktrees` namespaces. The label describes path context; creator, last use and disposability are not inferred. Arbitrary `ai`, `debug`, `.agents` or scratch-folder names are not evidence of agent origin. Agent workspaces can contain unique edits and commits and must be reviewed in their owning tool.

Developer checks also discover indexed `.git` directories and regular worktree pointer files when a recognized output has not already supplied that project's review. Repository/worktree records remain Protected and analysis only. Existing output limits (2,000 indexed candidates /250 reported artifacts /two-minute loop budget), metadata guard, ownership/exclusion checks and command bounds remain explicit. Artifact sizes are historical indexed file-only totals, not unique recoverable space. Prefix range queries use the existing primary key and do not walk unrelated paths for each artifact.

Git checks add fixed read-only `log -1 --format=%cI` and `rev-list --left-right --count HEAD...@{upstream}` operations. Only an upstream under `refs/remotes/` counts as a cached remote comparison; a local upstream, detached/unborn branch, missing graph or command limit leaves recovery unverified. Hooks, fsmonitor, optional locks, lazy fetch, replacement objects, inherited configuration and prompts remain disabled. No fetch, remote URL, credential, author, message, patch or file content is requested or retained. No GitHub or other remote service is contacted.

Indicators distinguish clean/dirty worktrees, commits absent from a cached remote, behind/diverged histories, cached matches and unavailable recovery. Cached refs may be stale. A match concerns HEAD's committed branch history and does not establish a current upload, every local branch/stash/reflog, ignored files, untracked changes or a backup of the directory. An Older commit label requires at least 90 days between the recorded check and HEAD's committer timestamp; it measures commit age, not inactivity or abandonment. Every generated-path disclosure retains Review before deleting. Supported output cleanup still needs its existing independent fresh exact-folder review, seals and explicit approval.

Storage reads reuse retained Git evidence with its check timestamp; browsing never launches Git or saves a report. Recheck artifacts explicitly collects current evidence. Reports and new optional/defaulted JSON fields remain schema 7; legacy records deserialize with unrecorded recovery and empty indicator lists. The helper remains exactly paired with the app and independently authenticates read requests. Coverage adds a validated optional permission-denial filter and current Rust-owned location guidance; see the [26-path review](../validation/permission-denials-2026-10-24.md).

Primary references reviewed 2026-10-24: [Git revision counting](https://git-scm.com/docs/git-rev-list), [commit date formatting](https://git-scm.com/docs/git-log), [Claude worktrees](https://code.claude.com/docs/en/worktrees), [Cursor worktrees](https://cursor.com/docs/configuration/worktrees). These establish supported concepts and common namespaces, not the creator or status of a particular user's folder. Custom agent storage, arbitrary build systems and current remote recovery remain unverified.

Validation and installed acceptance are recorded in docs/status.md. No existing user file is removed to test this feature.
