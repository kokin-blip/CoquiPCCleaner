# Phase 3.2 — remaining supported macOS diagnostic workflows

Direction contract: extend the incumbent Firmware & Security Operate workspace, preserving the system typography, neutral surfaces, mint actions, native navigation, existing logo and lack of repeated shield advisories. Add task tabs for chronological audit comparison and update notices/review reminders; retain Overview, Advanced audit and Guidance. Reuse evidence/status/history/table/field patterns. No new visual world, raster assets or blanket advanced-mode permission.

User selected in-app notices and optional review reminders; no macOS notification permission. Network update checks remain explicitly selected and consented per run. Reminders never collect optional data or contact Apple. Notifications open the exact retained audit, expose age and later failed-check gaps, and can be dismissed locally. Comparisons explain missing scopes/permissions and differences without certifying installation, version ordering or integrity. Manual follow-up links to a saved comparison while its outcome stays unverified. Existing Apple-managed installation/Recovery boundaries remain.

Acceptance: notice latest-response/failed-check/freshness semantics; opt-in disabled defaults; dismissal/reopen/coalesced due reminders; migration from schema4 and purge preserving preferences; chronological comparison, mismatched platforms, partial scopes and unknown/manual properties; exact-source routing; meaningful tests, native launch, minimum-size dark/light review, Figma handoff and local release. Hardware/OS/VoiceOver/distribution validation beyond this Mac remains explicit follow-up.

## Implemented behavior

- Compare finished complete/partial audits with strictly increasing timestamps. Same IDs, reversed order and unfinished/cancelled runs are rejected. Compare OS version/build, firmware/loader, SIP, authenticated-root, FileVault, manual startup policy and requested software offerings. Matching eligible model/chip/architecture/manufacturer allows a reading comparison; this is not physical-device attestation. Missing scope stays not collected, unavailable/manual/custom readings stay not comparable. All offering identities determine equality, including those beyond the compact display. A disappearing offering never proves installation. Saved comparisons copy selected evidence so source expiry does not silently rewrite them; comparisons expire on their own retention date.
- Update notices derive from the newest retained usable requested listing. A later complete none-offered response suppresses older offerings. A later failed/cancelled/unknown attempt preserves older offerings with explicit uncertainty. Partial, future/invalid-time or 24-hour-old listings are flagged stale/incomplete; even younger listings make no current-state claim. Dismissal records the exact source ID; a later explicitly requested listing can create a new notice. Toolbar and workspace actions open that exact source, including same-ID navigation from another tab.
- Review reminders default off, validate integer intervals 1–365 days, calculate next due in Rust and refresh locally on app startup/every 30 seconds while open. No closed-app scheduling, OS notification permission, automatic utility or Apple request. Missed intervals coalesce into one due notice; dismissal schedules now plus the interval. Saving an unchanged rule preserves its due time. Disabling clears next due. This schedule is independent from Maintenance.
- User-requested local observations after separate Apple guidance attach a saved comparison when available. Cancelled observation stays incomplete, and comparison errors are disclosed. Outcome always remains unverified. No writer, installer, reboot, startup-policy change, Revive or Restore is added.
- Schema 4 → 5 creates only `firmware_preferences`; existing data remains readable. Legacy audit model names and guidance comparison IDs have serde defaults. Normal retention removes diagnostic records. Diagnostic purge removes audits, comparisons, guidance and evidence notices, resets dismissed evidence ID, and preserves preferences and reminder/maintenance schedules. Settings names that distinction before removal. Disable reminders separately.

## Reproduction

Use the pinned lockfiles and `npm ci`, `npm run types`, `scripts/check.sh`, `scripts/release.sh`. No new dependency or notification entitlement was required. Generated TypeScript matches Rust. Version 0.7.0 targets aarch64-apple-darwin/macOS14+. Older releases reject schema5 rather than attempting to downgrade; preserve data/backups before manually using an older binary.

## Validation limits

Hardware remains physically checked only on Mac16,8 / M4 Pro / macOS26.6.1. macOS14, additional Apple Silicon families, managed/deferred update catalogs, complete VoiceOver use and other-Mac downloaded Gatekeeper behavior require separate hardware/distribution validation. Live readings and uncertainty remain as documented in phase-3-implementation.md. No new network update check, installation, reboot or recovery is necessary to test retained comparisons/notices. Firmware integrity and authoritative latest-version mapping remain unavailable. Original Flow H and future separately authorized operations stay preserved in the original brief/specification.
