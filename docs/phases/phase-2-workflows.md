# Phase 2.4 — remaining supported workflows (0.5.0)

Implemented 2026-10-22 on Apple Silicon macOS 14+. The original Phase 2 specification is preserved in phase-2.md; this document records actual capabilities and boundaries rather than expanding destructive authority.

## Where to use it

- **Ask Coqui:** local guided investigations with conversation history, clarification, named typed tasks, saved evidence/context and working page handoffs. This is a deterministic guide, clearly labeled, not an external/generative model. No diagnostic data is transmitted. Unknown topics request clarification; saved observations are never presented as current measurements or confirmed causes. Approval remains in Optimization.
- **Optimization → Duplicates:** explicit content analysis of the retained file index. SHA-256 selects potential groups; byte comparison confirms equality. Changed index sizes, inspection/hash identity changes and content edits between hashing and group verification are qualified gaps rather than stale equality claims. PNG/JPEG dHash candidates and possible modified copies are a separate advisory list with Finder inspection. Similarity never authorizes cleanup.
- **Optimization → Resources:** scoped developer/application/organization evidence. Existing Developer artifacts performs fresh Git/worktree validation. Shared common directories identify registered worktrees; equal local configured-remote fingerprints with distinct common directories suggest related clones, not equivalent contents or disposability. Raw remote URLs/credentials are not persisted. Relationship queries cover at most20 unique indexed repositories, respect current exclusions and cancellation, and run off the native UI thread.
- **Performance → Baselines:** declared workload/expected task/conditions, 6–600 second capture, actual two-second CPU/memory/swap/process-I/O samples, readable power observations, cancellation and retained summaries. Compare two completed records; mismatched protocols are disclosed. CPU and memory are not a benchmark or causal bottleneck diagnosis.
- **Performance → Manual plans:** record intended power/login change, readable previous state, manual System Settings instructions, explicit user acknowledgement, newly observed values, verification limits and manual recovery guidance. Coqui performs no power/startup mutation and never claims a modern login-item toggle was verified.
- **System Analysis → Workload & Upgrade:** representative baseline observations plus explicit demand/growth assumptions. Lower/declared/higher scenarios use demand × (1 + growth)^years; they are illustrative capacity assumptions, never lifespan or OS-support forecasts. Wear/support/cost gaps remain unavailable. Optional user-provided low/high/source quotes are marked unverified. No-change guidance is valid.
- **Maintenance:** disabled by default; opt-in reminders or read-only standard/selected-folder scans every 1–365 days while the app is open. Exact scope/exclusions are saved; newly added exclusions are also applied at execution. Deep scope needs manual confirmation and cannot be scheduled. Checks run every 30 seconds; missed occurrences coalesce once on reopen, active work defers them. The next due date is persisted before a scan, preventing an interrupted occurrence from replaying automatically. Filesystem capacity alerts are qualified for APFS sharing. No scheduled deletion, launch agent or background service is installed.
- **History → Activity:** paginated investigations, duplicate reports, baselines, manual plans, advice, resource reviews and maintenance outcomes. Pending manual plans can be inspected and completed/declined after restart. Existing cleanup history keeps exact approvals and per-item actual results/Trash locations.

## Content and cleanup policy

Duplicate analysis covers at most 2,000 indexed nonempty files, 256 MiB per file, 2 GiB initial hashing and a separate 2 GiB verification-read budget, with a 120-second outer bound. The current file may finish before the outer bound is checked; cancellation is checked per read chunk. At most 150 PNG/JPEG images up to 32 MiB, 12,000px and a 96 MiB decoder budget receive a 9×8 grayscale dHash; distance ≤6 identifies at most 200 review pairs. HEIC/RAW/video similarity, rotated/cropped matching, content search and exhaustive photo-library access are unavailable. Scope/read failures are retained; absence of a group is not proof of global uniqueness. Version-control metadata is excluded from content comparison. The UI pages ten groups at a time and shows at most the first100 copies per group, with an explicit narrower-scope instruction; protected paths show analysis-only explanations and cannot be selected for removal. File contents and image pixels are not retained.

Duplicate cleanup is separate authority (`duplicateCleanup`, default false for old records), supporting 1–50 explicitly selected copies from one confirmed group. The keeper must be a different group member and cannot be selected for removal. Only user-owned, regular, non-hardlinked files under Desktop/Documents/Downloads/Pictures/Movies/Music qualify. Library/system/app/project ancestry, symbolic links, cloud placeholders and exclusions remain protected. A standalone home package.json retains the earlier validated exception; repository/workspace markers remain boundaries.

Preview freshly hashes and byte-compares each copy with the keeper and captures both identities. The existing ten-minute, single-use approval journal and native Trash executor revalidate contents, keeper, exclusions and project ancestry twice before each move. Verification checks source absence, native returned identity, Trash content hash and unchanged keeper. A keeper changed during the native call makes the result unverified. Cancellation stops pending moves; an in-flight native move still receives verification. Trash does not immediately free capacity; Finder Put Back is conditional. Coqui never empties Trash or automatically retries uncertain actions. Concurrent writers/pathname races cannot be eliminated by this unprivileged pathname API; close editors/tools and retain valuable backups.

The completed cache-file and supported project-output policies remain unchanged. Dependencies/environments, unassociated Xcode DerivedData, Docker volumes/containers and emulator devices remain **analysis/manual review only**, with technology-specific consequences. No generic prune, repository/worktree removal, Application Support deletion, arbitrary command execution, permanent deletion or privileged helper is added. Application identifier matches are bounded observations, and missing associations are unconfirmed leftovers.

## Persistence and operation boundary

Rust owns schema 4: transactional `records` storage (typed serialized payloads, indexed kind/time/status) and a separate saved maintenance rule. Existing settings/scans/file index/cleanup/developer tables remain compatible. Running records recover as interrupted in both SQL status and payload after restart; no action is replayed. Records share configured retention (30 days by default). Removing diagnostic history clears all new diagnostic records; settings and the maintenance schedule remain preferences. The UI explicitly explains how to disable maintenance separately.

A shared Rust operation guard serializes scans, validation, approvals/execution, diagnostic jobs, preference changes and purge. Tauri commands/channels carry generated Rust-owned types. A global UI operation/cancel banner remains visible across navigation. Separate live monitoring stays bounded to 450 samples. No remote model, telemetry, account or automatic external fetch is added. Allowlisted reference links open the browser only when selected.

## Public references and qualifications

- [Apple power modes](https://support.apple.com/en-us/101613): mode availability and Battery/Energy guidance depend on the Mac. No undocumented `pmset` write is exposed; only `pmset -g custom` reads recognized numeric fields.
- [Apple memory/service guidance](https://support.apple.com/en-ie/102328): check the exact model's memory configuration/service options; Apple Silicon unified memory is configured at purchase. No Intel claim is made.
- [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice): registering an application's own helpers is not a general manager for other apps' login entries.
- [Docker disk usage](https://docs.docker.com/reference/cli/docker/system/df/) and [prune semantics](https://docs.docker.com/reference/cli/docker/system/prune/): host folder allocation is not daemon reclaimable storage. This build makes no daemon/remote-context connection and runs no prune.

## Retained extensions

Optional external AI requires a separately designed opt-in/data-preview/provider flow; none is connected. Autonomous conversational task planning, broad photo matching, native-manager resource execution, automatic setting mutation, OS-level scheduling while closed, independently fetched costs/compatibility forecasts and guaranteed recovery are not implemented. These capabilities remain in the full vision rather than inactive controls or unsupported claims. Phase 3, Windows and Intel remain deferred.
