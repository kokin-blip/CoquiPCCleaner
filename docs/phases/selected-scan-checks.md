# Selected scan checks — 2026-10-26 source preview

The user requested continued CleanMyMac feature work while preserving the agreed differences. This batch implements selected foreground metadata observations alongside storage scanning and a dated per-check review. It does not implement a combined removal/execution queue or broaden cleanup authority.

## Flow and scope

Scan Mac opens the existing scope review. Storage remains the configured standard, selected-folder or reviewed whole-internal-disk scope. Three additional choices start selected: System details, Startup configurations and Application inventory. Their copy explicitly discloses standard system/startup/Applications locations outside the selected storage roots. Unchecking them skips those collectors; choices reset for each new review. Cancelling the review starts no scan. The optional dialog footer keeps Scan and Cancel visible while a long mounted-volume list scrolls.

New `scan_with_modules` and `administrator_scan_with_modules` commands wrap existing storage operations; `ScanRequest` and the helper's typed operation/protocol are unchanged. The helper worker now uses an internal storage-only scan entry, suppressing its former implicit system/startup/application snapshot. Foreground observations run after storage traversal and, for administrator scans, after both existing public import loops succeed with the expected file count. They execute in the GUI/user process without administrator privileges and preserve their own dates. Storage counts, allocation and coverage retain their original meanings. Cancellation covers the selected checks as well as storage/import. A cancelled, failed or count-incomplete import starts no additional collection. This worker correction requires a future matching app/helper build; the installed pair has not been replaced.

No firmware/security audit, content duplicate/similar-photo read, online update check or maintenance action is implied by these three choices. Those remain separate explicit tools. Vendor-managed update installation, guided manual maintenance, local Ask Coqui, secondary developer/trial tools and empty removal selections remain in force.

## Collection and retention

Rust owns `scan_observations` and the macOS system adapter. Generated `ScanModules`, `ScanCheck` and `ScanObservations` types align Svelte/Tauri. Schema 7's existing typed records retain a report associated with the new scan ID; no migration is needed. Legacy retained scans are not rewritten. The older ordinary `scan` API keeps its previous snapshot behavior; privileged traversal now uses the storage-only entry for all helper scan jobs. Browsing starts no collection.

Each check records pending/running/complete/partial/unavailable/cancelled/notSelected state, attempt dates, nullable count, omissions and qualification. Restart recovery marks running reports interrupted; unfinished check states are normalized on pure reads without housekeeping writes. An unselected check cannot borrow a checked count/date from older global application inventory. No-count system readings, unknown counts and observed zero counts remain distinct. Complete means the bounded requested collection finished, not complete modern login coverage, an authenticated installed-app census or device health.

The system adapter reads current basic OS fields and a fixed hardware/display report, with a bounded cancellable stdout reader, twelve-second utility deadline and four-MiB output cap. No security or firmware command is added. Startup reads fixed launch-configuration directories; applications read system/shared/user Applications roots to three levels, treating bundles as leaves. Configured path exclusions, including normalized system aliases, are honored for these metadata paths and the actual `Contents/Info.plist` read target within a bundle. Enumeration is capped at 5,000 visited entries and a cooperative ten-second bound; metadata parsing has a separate ten-second bound and 32-MiB successful-read budget per check (at most one additional bounded read can reach the budget). Individual metadata reads cap at one MiB. These are cooperative bounds; blocking OS filesystem work is not a reserved-capacity or hard real-time guarantee.

Linked, cloud-only, nonregular, non-Unicode or unavailable metadata is omitted. Startup reads anchor parents with descriptor-relative/no-follow access on macOS, recheck identity/timestamps and reject oversized/control-bearing launch labels. Existing bounded bundle Info.plist reads are reused. No inspected file is modified. Observed applications update only Coqui's retained inventory, with scan-only protection/guidance and no associated-data or removal assessment; fresh inspection remains necessary. Unobserved/older app records are not declared missing by a bounded partial check.

Pure `scan_observations` and `scan_review` reads use current-schema connections without collection, Git, network, helper operations, work-guard acquisition or cancellation resets. Existing retention, diagnostic purge and interruption recovery apply. Failure to save selected checks is qualified in the terminal scan rather than establishing completed metadata observations.

## Presentation

Overview retains the four main destinations. What was checked shows the three dated check results without duplicating the old startup/application evidence rows. History reopens the same typed report without collection. Links to system/startup detail are shown only when the corresponding scan is selected; a report for another scan cannot silently navigate to current-scan results. Startup uses the matching retained check, including explicit unselected/cancelled state, instead of borrowing older snapshot rows. Separate-check links only open existing duplicate/update reviews; their content/network choices and approvals still occur there.
