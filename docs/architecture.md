# Architecture and data contract

Svelte renders engine data and collects scan/permission choices. A shared Svelte store owns application state and the bounded metrics buffer. Typed Tauri commands/channels handle IPC. Rust owns SQLite and all filesystem/diagnostic work. Tauri dialog APIs handle native folder selection. Narrow Rust commands handle Finder reveal and allowlisted System Settings destinations.

Rust modules: model (bridge-safe records), platform (allowlisted read-only macOS collectors), storage (metadata walker), database (migrations/queries), api (engine lifecycle and scan streams). Process execution uses fixed executable paths, argument arrays, bounded timeouts, and no shell interpolation. No privileges are requested by collectors.

Capabilities: supported, requiresPermission, manualOnly, unsupported, unknown, temporarilyUnavailable. Observations carry source/time/units/qualification. Scan states: running, complete, partial, cancelled, failed. Cancellation preserves partial results, and interrupted persisted runs are marked interrupted on startup. Missing collections do not erase successful collections.

Storage uses lstat, never follows symlinks, skips cloud placeholders and mount boundaries, deduplicates roots and hard links, and distinguishes logical/allocated bytes from filesystem capacity. The 0.8 whole-internal scope reviews all mounted internal volumes, using mounted filesystem identity alongside object identity and published APFS firmlink aliases. SQLite owns its frontier, deduplication and folder aggregation; see phases/whole-disk-cleanup.md. The metadata scanner performs no content reads, hashing or modification of inspected data. Separate explicitly requested Phase 2 content analysis is described below. Cache rules explain potential future cleanup; bytes are not promised recoverable.

SQLite is stored in ~/Library/Application Support/CoquiPCCleaner. Schema migrations run in transactions. Preferences, snapshots, evidence/findings and scan summaries persist locally; file inventory is replaced per successfully completed scope. Failed or cancelled scans remain inspectable without replacing a previous complete scope index. History defaults to 30 days. No raw file contents, serial numbers or command dumps in routine logging.

It never turns explanatory text into executable instructions. Native Foundation handles Trash; SQLite schema 2 persists review identities, approval, per-file intent and verification. See phases/phase-2-progress.md for eligibility, interruption/recovery rules and the pathname-race limitation. That legacy module exposes no permanent deletion, privileged helper or system-settings mutation API. The separately authorized 0.8 helper boundary is described below. ## Selected foreground scan checks — 2026-10-26 source preview

New explicit-module scan commands retain `ScanRequest` and helper protocol 2. Ordinary explicit scans bypass the legacy snapshot; the privileged fixed worker uses an internal storage-only entry. The requesting user process collects selected system/startup/application metadata after traversal or successful complete public import. No foreground collector starts after import failure, count mismatch or cancellation. The older ordinary scan API retains its legacy snapshot for existing callers; old records are not rewritten.

`scan_observations` owns bounded enumeration, exclusions including actual bundle Info.plist targets, per-check attempt dates, nullable counts and explicit partial/unavailable/skipped/cancelled state. The macOS adapter owns cancellable fixed system-report collection. Schema 7's existing typed records store each report under its scan ID. Pure reads normalize interrupted pending states without writes; Overview, History and Startup use that scan's evidence. Neither observation records nor summary links create removal, content-read, network or maintenance authority. See [selected scan checks](phases/selected-scan-checks.md) and [status](status.md) for actual validation and installed-helper limits.

## Broader cleanup categories — 2026-10-27 source preview

`cleanup_categories` owns twelve fixed standard-location definitions and pure report/page queries. Current-schema read transactions aggregate regular-file rows only through bounded primary-key path ranges, normalize published aliases/current exclusions and distinguish indexed zero from unavailable/excluded locations. The all-category report has no reclaimable-space sum. Pages contain at most 100 files; no caller-supplied root is accepted. Rule-review dates are independent of source scan dates. No collector, content read, Git/network/helper request, history write, work-guard acquisition, cancellation reset or schema migration is added. Tauri executes queries off the UI thread and generated types align with Svelte.

Cleanup Categories owns presentation, focus and empty/reset selections. Only user/Xcode cache file selections enter Optimization's existing fresh preview/approval path; no cache rule or executor is expanded. DerivedData links existing Developer review; manual/protected groups expose no removal selection. Guidance URLs join the exact allowlist and open only on explicit selection. See phases/cleanup-categories.md for query, scope and validation bounds.
